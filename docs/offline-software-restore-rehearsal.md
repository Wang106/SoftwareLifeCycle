# 离线合成软件文件备份／恢复演练

日期：2026-11-07（UTC+8）。这是标准库、Linux、本地合成文件演练，不是公司软件备份工具或生产恢复验收。原有 [PostgreSQL 隔离演练](isolated-synthetic-postgresql-backup-restore-rehearsal.md) 保持独立；本包不重复数据库备份、不连接数据库。

## 运行与证据

在仓库根运行：

```sh
python scripts/offline_software_restore_rehearsal.py
python -m unittest discover -s backend/tests -p test_offline_software_restore_rehearsal.py
```

CLI 不接受任何源、目标、导入、清理或输出路径参数；`--help` 只显示帮助。不读取环境配置、真实固件、公司文件、密码或连接串；无网络、安装、上传、数据库或服务器操作。不支持所需安全目录 fd 原语的平台直接拒绝，尚不支持 Windows。

每次在固定 `/tmp` 下独占新建 `software-rehearsal-<随机32位hex>` 私有目录；不使用 `TMPDIR`。临时根必须是 root 或当前用户所有，若组／其他用户可写则必须有 sticky bit。run 和内部目录采用 0700，文件采用 0600（更严格的 umask 可能使运行失败，不主动放宽权限）。

1. `source/` 创建固定三文件：小型固件 bytes、无秘密 sample-only 配置和说明。
2. 从真实源文件读取并核验字节后复制到新建 `bundle/`，写固定规范 JSON 清单：scope、version、随机 run ID、固定相对文件名、长度及 SHA-256。
3. 完整核验 bundle 后才创建 `restored/`。目标即使已有且为空也拒绝，不覆盖、合并或重试部分恢复。
4. 从核验过的备份字节写入恢复目录，再逐字节、长度及摘要验证恢复内容、源内容和完整备份。成功后生成 `result.json`，CLI 返回 `VERIFIED`、`SYNTHETIC_ONLY`、run ID、文件数、总字节及清单摘要。

所有内容固定且总量不足 8 KiB；每目录枚举至第 5 项即拒绝，单文件读取不超过受信预期长度加 1 字节。磁盘清单不作为路径输入或真实性来源：直接与进程内生成的固定清单逐字节比较，清单和文件一起篡改也不能成功。不存在 tar 解包、任意目录遍历或 JSON 深度攻击面。不同 run 的清单不能互换，也不提供跨进程恢复已有 bundle 的入口。

## 安全边界与失败行为

目录 fd 与 `O_NOFOLLOW`、`O_DIRECTORY` 固定访问对象；相对名称全部来自程序常量。文件用 `O_EXCL` 新建，只接受 regular 文件且链接数为 1；拒绝 symlink、hardlink、FIFO、目录及其他特殊文件。读取前后核验 inode、设备、类型、链接数、长度和修改时间，目录绑定在读写前后核对，检测替换竞态；`O_NONBLOCK` 避免替换为 FIFO 后阻塞。所有 fd 在正常及异常退出关闭。不会递归删除或自动清理任何目录。

失败输出固定 `BLOCKED` 与原因，不输出传入参数、原始路径、异常或文件内容；已创建的合成文件保留作调查。调用者可用输出 run ID 定位自己本次 `/tmp` 目录，人工核对后按所在环境的正常临时文件管理流程处理；本工具没有 cleanup 参数。磁盘满、权限不足、短写/零写、已有目标、损坏/缺失/额外文件或目录替换都不会被报成成功。失败之后不能继续向同一目标恢复。

这是私有进程和 0700 临时目录的本地安全边界，不是抵抗 root／同 UID 恶意进程的隔离沙箱。同 UID 可篡改进程内存、已打开对象或在目录检查与写入之间移动目录；fd 避免跟随替换路径，但不能把这种敌手变成可安全共存的主体。应在受控、无此类敌手的本地临时环境运行。成功只描述本次核验时的状态，不保证随后文件不变。
