# SSR/ASR 已记录审批路线漂移安全降级

本包只处理 `/demo/zfi` 的只读样例投影。当演示 API 的 `approval_routes`
缺失、格式错误、角色数量不符、顺序变化，或任一 SSR/ASR 角色与固定样例契约
不一致时，页面不得继续把待审记录解释为第 1–4 节点。

## 固定样例契约

- SSR：电子工程师 → 电子经理 → 系统工程师 → 研发总监
- ASR：应用工程师 → 应用经理 → 系统工程师 → 项目经理
- 两条路线必须同时存在、各有四项，并按上述顺序逐项精确匹配。

路线不匹配时，所有待审记录只能归入 `UNKNOWN` 并显示“节点无法确认”；页面显示
双语路线异常说明，不显示可被误解为已确认的路线进度。已关闭记录仍仅按它自身的
状态、关闭标记和空当前节点一致性判断，不会因路线漂移被重新解释为待审节点。

## 验证

`frontend/tests/zfi-demo-stage-filter.test.cjs` 覆盖完整契约、缺失路线、倒序、增删
角色、SSR/ASR 角色漂移、双语页面降级、数值节点无匹配、`UNKNOWN` 归类和关闭态
隔离。既有生产路由验证器仍验证正常固定路线下的 16 次真实 Next 生产路由读取。

本包不修改 API、数据库、Seed、依赖、身份、提交门控或部署配置。它不证明真实
审批人员、当前冻结 Snapshot 绑定、正式发布或公司环境部署；公共演示继续只读。
