# Chinese / English interface contract

All 63 existing page entry points, navigation, shared catalogs and all 14 command
preparation forms support Chinese and English. Missing or invalid preference uses
Chinese, including the initial server render. The global keyboard-accessible switch
changes text immediately and updates `html.lang` and the browser title. A language-only
`slc_language=zh|en` cookie remembers preference across navigation/reload (one year,
Path=/, SameSite=Lax, Secure on HTTPS). No identity or business data is in this cookie.
The shared not-found and error boundaries also have bilingual recovery text.

`frontend/components/localized.tsx` contains the provider and presentation boundaries;
`frontend/lib/i18n.ts` applies the Chinese dictionary and parameterized messages.
English is the original UI copy. Dynamic labels/statuses and validation messages use
the same presentation boundary; unknown customer-authored text stays as recorded.
Known demo notes and audit summaries have presentation translations; the original
stored evidence is unchanged. Unknown authored evidence stays as recorded. Brand names,
acronyms, IDs, hashes, URLs, filenames and code/JSON payloads remain unchanged. This is interface localization, not machine
translation of arbitrary customer records or a translation of the API protocol.

Translation never alters form values, select option values, UUIDs, enum tokens,
request_id, review/confirmation state, exact trace links, clipboard request JSON or
backend payloads. Every option declares its original explicit value. Changing language
does not reload/remount the workbench, regenerate keys, reset inputs or submit a request.
Business requests/credentials are kept in React memory; the language preference is the
only new browser persistence. Public staging remains read-only.

## Adding content

Wrap visible static text and direct dynamic text with `Localized`; translate display
attributes with `LocalizedAttributes`. Keep protocol/evidence output inside `code`/`pre`.
Add Chinese copy to `zh.json`; parameterized text belongs in `templates.json` with the
same interpolation slots. Preserve original option values and all handlers. New pages
inherit the root provider and cookie preference. Do not translate stored data on write.

## Verification

- Frontend unit tests cover dictionary/template validity, default/invalid language,
  Chinese/English SSR, whitespace, interpolated status/validation, immutable identifiers,
  and translated attributes with unchanged form values. AST coverage guards all pages
  and shared components against missing visible-text boundaries and implicit option values.
- Local production SSR: 63 existing routes × two languages = 126 checks, plus invalid
  cookie fallback and all 14 forms' identical raw input/option values in both languages.
  A mock unavailable API exercises page fallback/redirect behavior; this is not an
  authenticated write test. Browser switching/persistence is checked after deployment.
- The backend API remains 0.18.3 and schema 0017; no migration or backend change.
