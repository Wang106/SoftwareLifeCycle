# 从镜像交接包组装独立操作员目录

本工具补齐[离线只读安装指南](offline-operator-installation.md)第4节的文件复制与清单映射步骤。
它实际生成新的操作员输入文件，不是部署探针，也不导入或启动镜像。数据库就绪和只读角色声明始终
保持 `false`，所以生成目录不能直接通过现有运行配置预检。

仅新增组装器、专用回归及使用说明，并记录当前证据；旧验证器、测试、工作流、依赖、迁移和门禁不变。
本地准备不代表上传、发布运行时镜像、真实镜像交付或安装完成。

## 输入与输出

输入必须是已取得独立可信提交和清单SHA256的五文件交接包：

- `api.tar`
- `web.tar`
- `manifest.json`
- `evidence.json`
- 空的 `COMPLETE`

v1交接清单没有数据库版本字段。受信组装器代码仅允许精确源提交
`e2038a9462770a29254674dd86c0e7b26b26a221`，其源码迁移与同提交演练证明对应
`0030_private_upload_sessions`。旧提交、未知提交（包括未经单独审核的新工具提交）在创建
目标目录前拒绝。新增兼容提交必须经过源码/schema证据审核；不能靠用户填写版本、包内摘要或
两个当前常量一致来推断。此映射是兼容性约束，不是镜像来源认证。

通过兼容性检查后，工具使用原有严格验证器检查完整输入。不能从收到的包自行计算一个摘要，再把它当作独立可信
期望值。摘要一致性不等于签名认证、许可证审核或安全审查。

成功输出恰好四个文件：

- `api.tar`、`web.tar`：普通独立文件副本，保持原字节、大小和SHA256；不是链接或解包结果。
- `manifest.json`：新 `slc-offline-readonly-v1` 清单，只有 `format`、`source_commit`、
  `required_db_revision`、`images` 四个字段。两个镜像记录原样映射，版本来自审核过的精确源提交映射，当前唯一支持值为
  `0030_private_upload_sessions`。
- `operator.json`：沿用现有示例的五字段结构；`database_preprovisioned` 和
  `database_readonly_role` 都是JSON布尔值 `false`，范围仍为本机Linux、只读、仅合成数据。

不会读取或创建数据库凭据文件、`database.env`，也不会生成Compose或把原 `evidence.json`、
`COMPLETE` 复制到输出目录。
镜像内部内容仍需独立安全审查，逐字节复制不代表已排查所有内嵌敏感内容。
新清单不冒充原始交接清单，输出也不是新的五文件镜像交接包。

## 明确执行文件组装

需要受信、无并发修改的本地Linux文件系统和受信工具checkout。Windows候选准备机信息尚不能证明
可以原生运行此工具；不自动安装WSL、Docker或其他运行时。

`HANDOFF` 是现有原包的绝对路径，`NEW_OPERATOR` 是尚不存在的新绝对目录；它的父目录必须存在。
两个位置不能相同或互相嵌套，也不能经过符号链接。既有目录即使为空也不能复用。
原包和将来的私密配置输出还应与操作员目录分开放置，遵循原安装指南。

以下命令只在明确需要创建这份本地副本时执行；没有隐含默认路径或执行模式：

```sh
: "${HANDOFF:?填写原始五文件交接包绝对路径}"
: "${NEW_OPERATOR:?填写尚不存在的操作员目录绝对路径}"
: "${EXPECTED_COMMIT:?填写独立可信的40位提交}"
: "${EXPECTED_MANIFEST_SHA256:?填写独立可信的64位交接清单摘要}"
python scripts/offline_operator_assembly.py assemble "$HANDOFF" "$NEW_OPERATOR" \
  --run --expected-commit "$EXPECTED_COMMIT" \
  --expected-manifest-sha256 "$EXPECTED_MANIFEST_SHA256"
```

导入模块、查看帮助或缺少显式 `--run` 不会组装文件。未知参数、格式错误、错误可信期望值或无效
原包都必须停止；没有从旧日志恢复、跳过校验、自动更正清单或允许未就绪数据库的选项。

## 文件安全与完成边界

组装过程中保留原目录和文件描述符，复用已有不跟随链接、单链接普通文件、固定文件集合、严格
tar结构及哈希校验。不会先验证路径、再把重新打开的不同文件当作原输入。复制有界分块执行，输出
归档独立重新验证，写入JSON与预期规范字节比较；结束前再次检查原五文件。

沿用两个归档合计16GiB上限，创建输出前要求可用空间至少覆盖全部副本、元数据及额外1GiB。
这不是峰值容量保证，也不是预留磁盘配额。新目录和文件采用私有权限，不改变现有目录或文件权限。
源文件内容及修改时间保持不变；操作系统可能更新访问时间。

只有全部写入、验证、同步及关闭成功后才能返回 `OPERATOR_DIRECTORY_ASSEMBLED_NOT_READY` 回执。
它记录源提交、可信原清单摘要、新清单与operator文件摘要、两个归档、四个文件及归档总字节数。
`operator_ready`、`application_started`、`database_started`、`provenance_verified`、
`offline_accepted`、`deployment_approved` 全部为 `false`。没有路径、宿主信息、日志或凭据；
回执不是运行许可或来源签名。

失败、中断或关闭结果不确定时保留现有输出，不自动删除、覆盖、补写或重试。目录存在、四个文件
看起来齐全或JSON可读取，都不能代替成功结果。不要重新使用失败目录，也不要自行增加完成标记。
原始五文件包仍应保持原样，后续处置由操作员判断。

上述检查建立在受信工具、本地存储和无恶意并发修改的前提上，不声称抵御同UID恶意进程、管理员
或不可靠文件系统。

## 组装后仍需完成什么

对刚生成目录运行现有配置预检，应因两个 `false` 声明而拒绝，并且不读取秘密文件、不生成Compose。
这就是预期行为。不得为了让预检通过直接将声明改为 `true`。

实际数据库、迁移版本、非所有者/非超级用户的SELECT-only角色、私密连接输入和具体机器执行许可，
仍按原安装指南逐项取得。只有事实与授权均满足后，由获准操作员继续相应步骤。这个组装器不提供
数据库、建角色、授权、seed、镜像load/start、浏览器验收或公司部署功能。

真实镜像字节仍需在获准环境准备并保留。不能从已经结束的临时CI runner恢复此前没有保留的镜像；
本包不上传或传输文件，也不恢复任何待确认的GitHub操作。
