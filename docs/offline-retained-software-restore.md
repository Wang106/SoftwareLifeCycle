# 保留合成软件 bundle 的独立进程恢复

日期：2026-11-07（UTC+8）。本包仅扩展 [原合成演练](offline-software-restore-rehearsal.md) 的固定合成文件范围：原进程结束后，另一进程从保留的 bundle 恢复到随机新私有目录。不是通用备份导入工具，也不接受公司文件或真实配置。

## 操作契约

先运行原工具，单独记录其成功输出中的 `run_id` 与 `manifest_sha256`，保留 `/tmp` 中该次证据：

```sh
python scripts/offline_software_restore_rehearsal.py
python scripts/offline_retained_software_restore.py RUN_ID EXPECTED_MANIFEST_SHA256
python -m unittest discover -s backend/tests -p test_offline_retained_software_restore.py
```

将两个大写占位符替换成操作者先前单独记录的值。不要从待检查的 bundle 现算摘要后当作原始记录。入口仅接受 `software-rehearsal-` 加32个小写十六进制字符的 run ID，以及64个小写十六进制字符的清单 SHA-256。`--help` 不读文件。没有 source、target、输出路径、清理或任意文件导入参数，也不使用 `TMPDIR`。运行仍需原工具支持的 Linux 目录 fd 安全能力，不支持时直接拒绝，不降级。

原 run 与 bundle 必须由当前有效 UID 所有且权限精确0700；保留的 result、manifest及三文件须为同 UID、0600、regular、单硬链接。过于严格的 umask 也可能导致拒绝，不自动调整权限。固定 `/tmp` 必须由 root 或当前用户所有，若组／其他用户可写则需 sticky bit。仅打开原 run、bundle 和固定白名单文件；原 `source/` 与 `restored/` 不参与读取、修改或删除，它们不存在也可恢复。原 run 根目录不作为任意文件清单枚举。

## 验证后再分配目标

1. 在新进程内，按原工具固定版本1、固定三文件和输入 run ID 重建规范 manifest。先将重建结果与调用者摘要比对。
2. 按原工具成功报告格式重建 `result.json` 的精确字节。保留的报告必须完整匹配，包括 scope、VERIFIED、run ID、三文件数、1137总字节和 manifest SHA-256。不能仅凭磁盘报告的成功字段放行。
3. 读取固定 `bundle/manifest.json` 并与重建字节比较；bundle 的名称集合必须恰为固定三文件加 manifest，实际文件逐字节、长度和摘要验证。既不解析磁盘 manifest 为路径，也不信任其大小字段。manifest、文件和 result 一起篡改仍不能改变固定 fixture 契约。
4. 全部验证通过后，才在固定 `/tmp` 下独占创建另一个 `software-recovery-<随机32位hex>` 0700目录及其 `restored/`。任何已存在目标，即使为空，也拒绝；不会覆盖、合并或复用。
5. 将真实读取并验证过的 bundle 字节写入新目标，再从目标读取验证；再次核验原 bundle/result，写新的 `recovery-result.json` 候选证据，磁盘状态固定为 CANDIDATE，不是最终成功凭据。不重建原 source、不用硬编码 bytes 代替实际复制。

全部验证和关闭操作完成后，只有 CLI stdout 输出与退出码0一起才能确认本次成功；输出包含 SYNTHETIC_ONLY、VERIFIED、新 run ID、原 source_run_id、文件数、总字节和原 manifest 摘要。恢复 run 使用不同前缀，报告使用不同文件名和结构，不能递归作为原始成功备份基线。恢复目标不生成新的 bundle。

## 文件安全和失败行为

沿用原演练的目录 fd、NOFOLLOW、DIRECTORY、NONBLOCK与O_EXCL原语，原脚本和已有测试不修改。新入口额外检查文件权限／属主，并保存验证文件的身份、模式、链接数、大小、mtime/ctime及属主快照，之后每次守卫重新核验；目录句柄绑定也在读写前后检查。拒绝符号链接、硬链接、FIFO、目录替换、权限变化及已观察到的读写竞态。目录枚举至第5项拒绝；读取长度受固定预期限制且不超过预期加1字节，单文件上限8192字节。输入长度在正则前检查，不读取配置、凭据、环境源目录或网络。

成功与异常路径对登记的目录 fd 逐个单次尝试关闭，一次关闭失败不阻止其余句柄的关闭尝试；文件 fd 在各自 finally 中单次关闭。任何关闭错误使本次整体失败；关闭结果不确定时不盲重试同一 fd，也不承诺内核错误下所有句柄都成功关闭。失败返回非零及固定脱敏 BLOCKED，不输出参数、原始路径、异常或文件内容。已创建的部分目标保留，没有删除／清理／重试部分恢复机制；对象内失败后不能继续恢复。工具从不删除未知资源。最终报告部分写入、fsync、close或最终守卫失败时也可能留下完整或不完整的候选证据，但其中不含 VERIFIED；即使候选文件完整也不得据此推断成功。操作者应在受控环境正常管理自己保留的临时证据。

摘要只是绑定，不是签名或来源真实性证明。属主／模式及固定字节校验不能证明文件确实由某次工具进程创建；能够伪造完全相同固定字节与原报告的同 UID 主体不在可信隔离范围内。这里明确不抵抗 root 或同 UID 恶意进程，不保证检查瞬间以后对象不变，也不宣称消除所有并发竞态。请在受控本地环境运行。

## 回归和验收边界

先新增真实双子进程回归，确认新入口不存在时失败，再实现。原进程必须完全退出，第二进程才恢复；测试将自己生成的 source 移到同测试拥有的临时目录，证明不依赖原 source。前后比较 bundle 内容，并核对新目标实际字节。

新增28项测试覆盖错误摘要／run、成功基线缺失／伪造、manifest与bytes与result联合伪造、恶意路径、不完整或超量bundle、symlink/hardlink/FIFO、私有权限、已有run／restored／文件、stat/open替换、读时文件／目录／权限变化、目标路径替换、短写／零写／部分写入／fsync失败、失败证据保留、无复用、描述符关闭、CLI脱敏及恢复报告不能递归信任；另覆盖最终报告写入／fsync／close／末尾守卫失败，以及目录close错误后继续逐fd一次尝试且整体BLOCKED。测试仅创建和管理自己拥有的合成资源。
