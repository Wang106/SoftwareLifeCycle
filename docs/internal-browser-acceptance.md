# 内网离线部署与真实浏览器验收
更新：2026-10-08（Asia/Shanghai）；模式：Codex。
用户确认：已有独立内网测试环境，仅可连接内网、不能连接外网；公司SSO/OIDC暂不确认；管理员、发布审批和生产授权人员由使用者自行指定。

## 两类验收及需要用户做什么
| 验收 | 可验证内容 | 用户准备 |
| --- | --- | --- |
| 公共演示浏览器 | 默认中文/英文、导航、布局、只读信息、禁用登录与错误状态 | 在本人浏览器打开公开站点；如希望助手控制浏览器，需明确允许访问该站点并接受访问提示。上次访问被拒绝，本包不重试或绕过 |
| 内网真实身份 | 登录/注销/过期、真实管理员目录/详情/历史、角色拒绝、受控业务操作 | 内网完整测试部署、可信HTTPS、后续确定的内网OIDC、独立样例数据库及自定测试身份。云端助手未获得内网连通能力，不能直接声称代为验收 |

公开只读演示没有配置OIDC，不能通过那里验收真实管理员操作。当前管理UI只有读取，新增/暂停/恢复授权及完整业务提交尚未全部完成；不要提前验收不存在的功能。

## 内网拓扑与交付方式
浏览器、Next.js前端、FastAPI、PostgreSQL和将来身份服务均应位于可互通内网。Next.js服务器需要访问API；前后端服务器需要访问OIDC的内网授权/token/JWKS端点；浏览器需要访问授权页和回调。公网Cloudflare前端没有已批准的内网连接，不将它当成此环境的入口。

GitHub Actions在外网执行测试和构建；在联网构建环境准备固定提交的前端/API镜像、数据库镜像、所需运行依赖、迁移与配置模板及SHA256清单，然后按公司批准方式导入内网。内网启动不得依赖docker pull、npm install、pip install或远端JWKS。现有docker-compose.yml及Dockerfiles需要下载镜像/依赖，不能直接当成离线安装包；前端认证环境变量尚须补充到公司部署配置。本包只是规划/验收手册，没有生成或演练离线镜像包。

完全不能出网的机器不能直接使用GitHub云端工作流自动拉代码/部署。本版采用云端测试打包→人工导入内网→内网部署验收；后续可按公司批准的内网CI/镜像仓库实现内网自动化，不虚构公网连通条件。

## 待准备信息（暂不要求确定提供方）
- 服务器操作系统/CPU架构、内网域名、HTTPS证书方式，以及是否可运行Docker/Compose。
- 前端/API/数据库部署位置、端口及内部连通；无需公开密码或内网机密地址。
- 公司允许的版本包导入方式和负责部署的人。
- 身份方式后续确定：已有内网OIDC或经批准部署的内网身份服务；不使用外部提供方。所有issuer/audience/JWKS/token/回调都需满足现有协议。
- 测试用户由用户指定；按项目/软件范围配置角色，不在代码中硬编码真人或自动赋予管理员。

## 实际验收步骤
1. 导入固定提交安装包，记录commit/镜像digest及校验和；部署独立样例数据库，核对迁移0020，健康检查通过。真实公司数据暂不导入。
2. 配置内网可信HTTPS；当前浏览器会话要求HTTPS，不能通过忽略证书警告完成验收。配置与密钥仅由内部部署人员保管。
3. 身份服务确定后，配置issuer、API audience、client、授权/token/JWKS及精确/auth/callback；浏览器登录和服务器token/JWKS路径均在内网。先保持只读，验收身份/授权读取。
4. 指定独立测试用户：平台管理员、普通用户、评审人、发布授权人和生产授权人；现有确切角色名称/作用域以backend/app/security_roles.py为准。管理员授予流程另按管理操作实现与离线operator手册，不随启动自动创建。
5. 用真实浏览器验证中文/英文、登录、注销、过期及复制会话撤销；普通用户访问管理页拒绝，管理员查看三类目录、精确UUID详情和分页历史。
6. 核对历史显示的是授权状态事件，空历史不证明未修改；并发时详情与历史可来自不同读取快照。
7. 后续可写界面完成后，在独立受控环境验收授权拒绝、幂等重试、并发冲突、结果恢复和审计；通过后才考虑真实数据。
8. 保存浏览器/系统版本、commit、日期、步骤、预期/实际结果、脱敏截图/错误码。不得在截图或报告中包含密码、token、Cookie或数据库连接串。

当前缺口：离线交付包与内网部署演练、可信HTTPS/身份配置、真实浏览器权限和人员角色验收。不能把CI mock-provider测试计为这些验收完成。
